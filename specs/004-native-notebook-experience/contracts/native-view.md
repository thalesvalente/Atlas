# Native View 1 — conteúdo de apresentação, não protocolo científico

Um pacote RO-Crate 1.3 / Caderno 0.1.0a1 existente contém Files de `encodingFormat=application/vnd.atlas.native-view+json` (V1) ou `application/vnd.atlas.native-view+zlib` (V2 de transporte comprimido), com cp:sha256 e contentSize obrigatórios. Não há novo @context nem alteração do SDK. O viewer lê somente esses Files explicitamente incluídos no pacote fixado na CLI.

Cada chunk: `{format:"atlas-native-view",version:"1",revision:string,ordinal:integer,entries:[...]}`. Ordinais contíguos, revisão única. Entradas têm uid único derivado de coleção/posição, kind (record/node/relation/table/row/asset/collection), group, title, native_id/source_key/parent_key opcionais, fields como pares nome/texto/tipo e raw_json com JSON original. Linhas têm table_uid e cells textuais com tipo/ausência explícitos. Nenhum uid é identidade científica. Conteúdo desconhecido continua em collection/raw_json. O consumidor não reinterpreta IDs nulos nem status desconhecidos.

Manifesto do root declara revision e entryCount por namespace de apresentação. Limites do pacote **armazenado e validado pelo SDK**: metadata2MiB, File8MiB, bytes32MiB, 100000 entradas, 10000 nós. Quando a soma dos chunks JSON V1 exceder 32 MiB, a exportação tenta **V2 de transporte** sem alterar o protocolo: zlib nível 6 apenas sobre os Files de apresentação, com seus hashes `cp:sha256` e `contentSize` correspondentes aos bytes comprimidos. No root, `presentation#version="2"` e `presentation#logicalBytes` declaram o total lógico; cada File traz `presentation#rawSize` e `presentation#rawSha256` para os bytes antes da compressão. Conteúdo de cada chunk, JSON canônico e `version="1"`, permanece igual; a decomposição não reescreve valores ou IDs.

V2 exige: cada File verificado pelo SDK (até 8 MiB armazenados); soma física até **32 MiB**; cada bloco expandido limitado a **8 MiB**; soma lógica até **256 MiB**; stream zlib completo, sem dados extras; tamanhos e SHA-256 do conteúdo expandido iguais ao manifesto; sequência sem lacunas, contagens e digest da projeção original intactos. V1 continua aceito sem compressão, sem migração. Se V2 também exceder limites, falha explícita `NATIVE_COMPRESSED_AGGREGATE_LIMIT_NO_TRUNCATION` ou `NATIVE_LOGICAL_LIMIT_NO_TRUNCATION` — **nunca trunca, omite ou seleciona primeiras N ocorrências**. Falhas de quota, formato, digest, ordinal, duplicidade ou revisão invalidam a fonte inteira, nunca truncam dados. UTF-8 e JSON finito sem chaves duplicadas. Conteúdo original preservado em strings JSON para evitar arredondamento em JavaScript.

GET /api/notebook não aceita path ou URL do cliente. Retorna fontes por source_id, metadata_sha256, revisão, estado e entries. GET /notebook entrega apenas assets do produto. Sem upload, HTML importado, scripts remotos, iframe, acesso automático a links ou autoridade de ciência. Fontes não nativas continuam válidas no viewer de protocolo existente.

A exportação é local e exige escolha explícita do produtor/Caderno. O pacote deriva dos valores retornados pela API original e não certifica autenticidade da ciência ou segurança de host adversarial. Navegação de parentes usa chaves estruturais únicas no grupo; repetições/ciclos permanecem observáveis e não autorizam fusão de entidades.
